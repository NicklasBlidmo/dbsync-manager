*Written by Claude Code from the brief `2026-10-21`, implemented in the

## What changed

| Part | Change |
|---|---|
| A | `supervisor/content.py`: for every table whose counts agree in base and modified, one statement (`FULL OUTER JOIN` on the GeoPackage primary key from `PRAGMA table_info`, `IS DISTINCT FROM` per column, `ST_AsEWKB` byte equality for geometry columns found in `information_schema`, a `uuid` column's value when there is one) returns the differing rows capped at 200 with the three totals as window counts. `gather` runs it inside the check's database connection when `DBSYNC_CONTENT_CHECK` (default true) and logs the time; `evaluate` stores counts and sample on `SyncStatus.content_diff` (migration 0014) and raises `content_divergence:<file>:<table>` in a one-way or Reader-with-writers project (error level, health `diverged`, mailed like the count rules); in a two-way project nothing is raised and `run_project_check` writes one info event when the first difference appears and one when it clears. The connection table shows a per-table badge |
| C | `SyncStatus.tables` holds the GeoPackage's layer list with geometry column (from `gpkg_geometry_columns`) as the check read it; `facts.tables_for(project)` adds the schemas and whether `skip_tables`/`include_tables` leaves a layer out. Project page: a collapsed Tables section |
| E | `manager/api/`: `GET /api/v1/projects/`, `GET /api/v1/projects/<id>/`, `POST /api/v1/projects/<id>/verify/`, `GET /api/v1/operations/<id>/`. `registry.ApiToken` (migration 0015): name, user, SHA-256 hash, prefix, created, last used (written at most once a minute), revoked; the admin generates the secret and shows it once. `Authorization: Bearer`; 401 with `WWW-Authenticate` without a valid token, 403 without the user's permission, 405, 404, 409 as JSON `{"error": ...}`. No cookies, no CSRF. `docs/api.md` with one example per endpoint and the stability promise |
| B | `Operation.Kind.VERIFY`, steps `["verify"]`; the operation does not own the project (no block, no stop: the daemon keeps running). `supervisor/verify.py` runs `geodiff diff --driver-1 sqlite "" <gpkg> --driver-2 postgres <conn_info> <base> <changeset>` then `geodiff as-summary`, the two commands db-sync's `_compare_datasets` runs, per connection with a private TMPDIR; the result (`ok`, per connection `tables` [{table, insert, update, delete}] or `error`, `seconds`) is stored in the operation's params and shown in the operation panel. A difference raises `checkout_inconsistent` at error level with the slice 14 text; a connection that could not be compared fails the step. Started from the Verify button (operators), `manage.py verify --project`, or the API |
| D | `facts.state_for(project)`: identity, desired/process/health with since, direction, versions (server max, checkout and database min), last pull confirmed by the database, last attempt, last check, active conditions with since-times, the count-rule keys, content divergence per file and table, the last verification, and every connection's facts. The API returns it; the page reads the same helpers |

Settings: `DBSYNC_CONTENT_CHECK` in `settings.py` and `.env.example`.
Permissions: `apitoken` in the registry models (viewers read the list,
admins create). Ten connections per project needs no code: nothing in
the manager assumes a count.

## Tests

- `tests_content.py`: the skip rule, the plan (key, geometry, uuid), the
  statement's join, EWKB comparison, uuid and cap, shaping of the window
  totals and sample, GeoPackage key and geometry columns from a real
  SQLite file; evaluate: one-way and Reader-with-writers raise at
  `diverged`, two-way only stores; an unchecked round keeps the previous
  result. Tagged `db`: the statement against the test PostgreSQL with a
  row changed, a geometry changed (Z only; EWKB differs), one row only in
  base and one only in modified; the geometry part runs only when the
  test database has PostGIS (the test profile's database is created from
  `template1`, so today it skips the geometry column; set
  `TEST.TEMPLATE = template_postgis` to cover it).
- `tests_operations.py`: verify is one step, cancellable, never destructive.
- `api/tests.py` (db): token required and revoked refused, a session is
  not enough; a viewer reads both GET shapes with every documented key;
  verify needs an operator, creates one operation, 409 on the second,
  405 on GET; the operation endpoint and `last_verification` show the
  result.
- `ui/tests.py` (db): the Verify button creates the operation once, the
  Tables section renders, a viewer gets 403.
